# Limitations

- **One Tailwind root per app.** A Next.js app with several independent Tailwind themes has no single correct `twMerge`; the plugin errors and asks you to pick one via the `css` option. Monorepos are fine — each app's Next.js config gets its own plugin instance and its own generated config, including theme files imported from shared packages outside the app directory.
- **Next.js 16 and up, Turbopack or webpack.** The plugin relies on the loader rule conditions Next.js 16 added to `turbopack.rules`. Other bundlers are covered by [@tailwind-merge/vite](../../vite/README.md), which shares the same core.
- **A `tsconfig.json` or `jsconfig.json` is required under Turbopack.** Turbopack only applies loader rules to installed packages when one exists — see [how it works](./how-it-works.md#turbopack-and-your-compiler-config). The plugin warns when it finds neither next to your config.
- **Tailwind CSS v4 only, currently the v4.3 line.** The supported line is stated as a peer dependency range, so your package manager flags a Tailwind upgrade the plugin hasn't been validated against ([details](./how-it-works.md#version-alignment)). The range widens as the test matrix does.
- **Coverage.** The App Router, the Pages Router, `next dev`, `next build`, and both bundlers are what the test suite exercises today, on macOS and Linux. Middleware/proxy, the edge runtime, custom servers, and Windows are expected to work but not covered — reports from real setups are very welcome while the plugin is pre-1.0.
- **The runtime import is only generated inside the Next.js compiler.** Jest, Vitest, scripts, and other tools that import `@tailwind-merge/next/runtime` without running the Next.js build get tailwind-merge's default configuration — the same exports, just without your theme.
- **Externalizing the package disables the plugin.** The plugin adds itself to `transpilePackages` so the Pages Router's server bundle processes the runtime module; listing `@tailwind-merge/next` in `serverExternalPackages` would undo that and serve the default configuration on the server.
- **Classes must exist at generation time.** The config is generated from your CSS configuration, and in production builds pruned to the classes found in your sources (Tailwind's sources, found Tailwind's way — see [how it works](./how-it-works.md#pruning-to-the-classes-you-use)). The generated config describes the selected theme; classes from another Tailwind setup may not be classified correctly, and class names that reach `twMerge` from outside your sources while being styled elsewhere need `prune: false`.
- **Encoding and inferred conflicts.** Compact mode can overmatch names outside a finite theme scale. Exact mode avoids that named-scale overmatching but does not fully validate arbitrary CSS values. Custom-utility inference is conservative for partial overlaps and conditional/pseudo-element styles; the [configurator limitations](../../configurator/docs/limitations.md#classification-and-custom-utilities) also apply here.
- **Pruning is not an allowlist.** Lists drawn from scanned candidates retain the full config's merge behavior, but retained validators can also match unscanned names. Extensions must not assume that a pruned group still exists.
